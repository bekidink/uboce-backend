# Deploying to Render

The backend deploys as one [Render Blueprint](https://render.com/docs/infrastructure-as-code)
(`render.yaml`, generated by `pnpm render:generate`). The database is Supabase.

| Resource | Render type | Notes |
| --- | --- | --- |
| `uboce-gateway` | Web service | The only public API entry point. Health check `/health/live`. |
| `uboce-<name>` × 21 | Private services | Reachable only on Render's private network. Each runs its own migrations before every deploy (`preDeployCommand: npx prisma migrate deploy`). |
| `uboce-storage` | Web service + 10 GB disk | SeaweedFS (S3 API). Public, because browsers upload and download files with signed URLs. |
| `uboce-redis` | Key Value | Event streams, rate limits, session revocations. `noeviction`, private network only. |
| Postgres | Supabase | One schema per service through the pooler (see the README's "Database" section). |

All services are in Frankfurt, the Render region closest to Supabase's eu-west-1. Every
service builds from the same `Dockerfile`; the `TARGET` environment variable (passed to the
build as a build argument) selects which one, and only that service and the workspace packages
it uses are compiled.

**Cost:** 24 resources on the Starter plan, roughly 22 × the Starter instance price plus Key
Value and the disk. Private services can't use Render's free plan.

## 1. Before the first deploy

1. **Database.** `.env.supabase` points at the production Supabase project, `pnpm db:supabase`
   has created the schemas and `pnpm migrate` has run (later migrations run automatically on
   each deploy).
2. **Domains.** In `scripts/generate-render.mjs`, set `APP_URL` (the web app: CORS origin and the
   base of emailed links) and `STORAGE_URL` (the storage service's public URL; Render's default is
   `https://uboce-storage.onrender.com` if the name is free, or a custom domain). Then:

   ```bash
   pnpm render:generate
   ```

3. **Secrets.** Generate production secrets (new signing keys, MFA key, service credentials, S3
   keys; database URLs from `.env.supabase`) into the git-ignored `secrets/render.json`:

   ```bash
   DEPLOY_ADMIN_EMAILS=you@company.et \
   DEPLOY_SMTP_URL='smtps://user:pass@smtp.provider.com:465' \
   pnpm deploy:secrets
   ```

   `DEPLOY_PROVIDERS` adds signed payment/carrier webhooks (`name:kind:secret,…`). Re-running keeps
   existing values; `--rotate` replaces them (this signs everyone out). Keep `secrets/render.json`
   somewhere safe — it's the only copy.

4. Commit and push `render.yaml` (never `secrets/` or `.env*` files).

## 2. Create the Blueprint

1. Render dashboard → **New → Blueprint** → choose this repository. Render lists the 24
   resources and asks for the `sync: false` values; leave them empty — the next step fills them.
2. Push the secrets and start the first deploy:

   ```bash
   RENDER_API_KEY=rnd_… pnpm deploy:push-env            # dry run: shows what it would set
   RENDER_API_KEY=rnd_… pnpm deploy:push-env --apply --deploy
   ```

3. **Push notifications (optional).** On `uboce-notification` → Environment → **Secret Files**, add
   `firebase-service-account.json` (the Firebase service-account key). Without it, pushes are logged.

## 3. Check it

- `https://<gateway>.onrender.com/health/ready` returns `{"status":"ok"}` once all 21 services are up.
- Sign in as the admin email from `DEPLOY_ADMIN_EMAILS`: register it, confirm the email, turn on
  two-step verification — it then has the admin role.
- The API docs are off in production (`DOCS_ENABLED=false` on the gateway); turn them on there if wanted.

## The web app

`uboce-web` deploys separately, e.g. as a Render **Static Site**: build `pnpm build`, publish
directory `dist`, environment `VITE_API_URL=https://<gateway domain>`, and a rewrite rule
`/* → /index.html` so client-side routes load. Its origin must equal `APP_URL` above.

## Day to day

- Pushing to the default branch deploys every service whose image changed (`autoDeploy: true`);
  storage deploys only manually.
- New migrations ship with the service and run before its new version starts.
- Adding a service: add it to `infrastructure/services.json` as usual, then `pnpm render:generate`,
  `pnpm deploy:secrets` (gives it credentials and updates Identity's list) and
  `pnpm deploy:push-env --apply --deploy`.

## Railway instead

The same images run on Railway: one service per entry above, built from the `Dockerfile` with a
`TARGET` variable, a Redis plugin instead of Key Value, a volume on the storage service, and peer
URLs from Railway's private networking (`http://<service>.railway.internal:<port>`). Set the values
from `secrets/render.json` as service variables, and `npx prisma migrate deploy` as each service's
pre-deploy command.
